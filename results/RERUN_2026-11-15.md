# Re-run of 15 Nov 2026 (decisions D38–D42)

The changes Sanjiban decided after reviewing the team package, and every result re-run with them. MATLAB R2025a. "Before" is the team handover package of 15 Nov; "after" is this re-run.

## 1. What changed

| # | Change | Files |
|---|---|---|
| D38 | **The prefilter gets one zero.** y_k = α y_{k−1} + β u_k + β₁ u_{k−1}, matched so F·T·P = 1 up to s² on the real sampled loop. α = 0.9085, β = 0.3139, β₁ = −0.2224: pole 0.521 s, zero 0.145 s. It removes the D33 residual: the s² term goes from −0.046 to 0, and the s³ term left over is −0.0044. | `prefilter_design.m`, `reference_shaper.m`, `params.m` (`prefilter_zero`), `sensitivity_analysis.m`, `test_shaper.m` |
| D39 | **Sanjiban's firing rule.** Fire when `est.valid`, \|d̂\| < 2 m and P_hit ≥ p*, plus the 1.01 s recharge. The turret-rate match and range check are dropped. **p* refitted on Train-G: 0.95.** | `fire_logic.m`, `params.m`, `compare_designs.m`, `run_scenario.m` |
| D40 | **Metrics of `TESTING_VALIDATION_METRICS.md`** on train, test and validation: M1–M4 and E1–E4. Estimator statistics count each independent drone+noise run once. The confounded OLS θ̂ = a + b·θ table is removed. | `metrics_report.m` (new), `compare_designs.m`, `evaluate_tvt.m` |
| D41 | **Estimator reset aligned with D19.** Only a jump back in time of more than 0.5 s starts a new track; smaller steps back (ODE solver) keep it. Before this fix, a call at 1.0003 s followed by the 1.000 s reading wiped a 20-reading track. Now covered by check 7 in `check_estimator`. | `estimator_step.m`, `estimator_tests/check_estimator.m` |
| D42 | **Clean-ups.** The estimator values moved into `params.m` (Frozen, D30). CA is comparison-only, not a backup. Valid time stated correctly (0.20 s). The wording on blackout bias is corrected (a small coasting lag during turns exists). Block diagram redrawn. | `params.m`, `TUNABLE_PARAMETERS.md`, `docs/tvt_parameters.md`, `results/TVT_README.md`, `README.md`, `docs/diagrams/` |

**Reproducibility of Train-G (checked).** Re-running the original, unmodified package code regenerated every gate-result row of `compare_designs.md` exactly. The scenarios use fixed ids and seeded noise.
- Two summary lines ("blackout end → next hit") differed by 0.01–0.05 s.
- Those lines use the pulses of whatever gate was the default when the file was written, so the old file was most likely made before 0.99 was frozen.
